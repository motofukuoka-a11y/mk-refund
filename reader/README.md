# 払戻読取

既存MK払戻サイトと独立した、普通片道乗車券の旅行中止読取サイト。
既存サイトの計算画面とは独立した /reader/ ページです。

## 使用方法

1. カメラを許可し、回転ロックを解除してスマホを横に持ち、切符1枚を横長の枠いっぱいに撮影します。写真選択も利用できます。背景が多い場合は「切符だけを切り出す」で赤枠を確認・調整します。
2. 「この写真を読み取る」で端末内OCRを実行します。
3. 発着駅・発売額・旅客区分・割引種別を券面と照合し、経由駅を補います。
4. 旅行中止駅、有効期間内の確認、入力内容の確認を行い計算します。

写真と読取文字はアップロード・永続保存しません。OCR・計算はブラウザ内で実行。
Worker・WASM・日本語モデル・運賃データは同一サイトから取得します。
CSPのconnect-srcをselfに限定し、外部OCRやCDNを使いません。
初回データ取得には通信が必要で、完全オフライン起動は未対応です。
カメラは撮影・閉じる・ページ離脱で停止します。許可拒否時は写真選択が使えます。

## 計算仕様

元券の実発売額 − 元券経路から切り出した既乗区間運賃 − 220円。
割引条件を既乗区間だけで満たす場合は割引運賃、それ以外は無割引運賃を控除します。
営業キロ・混在線換算・運賃表はMK払戻 main 8f463ffを基準に共有。
既存仕様に合わせて未使用営業キロ101km以上を自動計算対象とします。
割引後の10円単位切上げも既存discount_rules.json/Version 5.2に合わせています。
元券発売額はOCR後に券面確認する実額を使い、全区間運賃の再計算額では置き換えません。
根拠：JR北海道旅客営業規則第274条。
https://www.jrhokkaido.co.jp/network/guide/pdf/yakkan_02_07.pdf

## 対象と制限

JR北海道内の登録駅・運賃表による普通片道乗車券のみ。
事故払戻、特急券、往復/連続、企画券、市内制度などの特殊条件は自動判定対象外。
読み取りは入力補助で、券面の全条件を自動判別するものではありません。
複数金額や割引表示が曖昧な場合は確定せず確認入力に戻します。
経由・有効期間・同行・証明書条件は券面等の確認が必要です。
小児への割引併用は制度条件が未定義のため自動計算を停止します。
対象外券の見落とし、小児判定や金額の誤読、退色・斜め撮影・地紋の強い写真の失敗は残ります。旅客区分が読めない場合は大人に決めず、利用者の確認を必須とします。

## AI読取版4（2026-10-05）

- TesseractからPaddleOCR JS 0.4.2 / PP-OCRv6 tiny detection + small recognitionへ読取エンジンを交換。新たな学習・Claude利用は行っていません。
- 写真から文字領域を検出し、座標に基づいて同じ行を組み立て、離れた発着駅名を解析します。低い認識確度の文字は入力候補から外します。
- 元写真を読み、必要なときだけ青成分を用いた濃さ調整で再読取。金額帯は縦の管理番号を避け、紫色の押印を抑えて追加読取。円記号・認識確度・金額形式がそろう場合だけ補います。異なる候補を勝手に統合しません。
- 撮影・切り出し・回転・特急券/グリーン券判別を維持。料金内訳からの一体券検出、市内制度の対象外チェックを追加。
- OCR Worker、モデル、WASMは同一サイト内に同梱。外部OCRは呼び出しません。Workerの通信も同一オリジンに制限。写真や読取文字の保存・送信はしません。
- 初回データ約46MB。ページ内ではエンジンを再利用し、2枚目以降の起動負荷を減らします。キャンセル時はWorkerを終了します。
- 公開写真25枚を元写真・手動切り出しなしで再読取。登録発着駅のある2枚では駅ペア一致1/2→2/2、普通運賃6枚では発売額一致4/6→4/6でした。金額の全体一致率は改善していません。旧方式で失敗した170円を読める一方、220円など2枚は未判別です。出典・期待値・新旧比較は [benchmarks/results-v4.json](benchmarks/results-v4.json)。写真は配布しません。小標本でありスマホ全般の精度を表す数値ではありません。

### 再ビルド

`npm ci --prefix reader/ocr-build`、`npm run build --prefix reader/ocr-build`。
SDK/ONNX Runtime/OpenCV/ビルド依存を固定。配布モデルとWASMはvendor/paddle-v4内。モデル公式URLとSHA-256はmodels.json、ライセンスはNOTICE.mdとlicenses/を参照。

### 写真比較を再実行

`npm ci --prefix reader/ocr-build` と `npm ci --prefix reader/benchmarks` の後、リポジトリを8765番ポートで配信し、`node reader/benchmarks/run.mjs /写真フォルダの絶対パス` を実行。
sample-00.jpg〜sample-24.jpgは出典一覧に合わせて各自用意してください。結果は写真フォルダのreader-benchmark-v4.jsonに保存。ブラウザと同じ認識関数・画像寸法・追加金額帯・再読取条件を使用します。カメラ撮影や端末性能の測定ではありません。

## 券種の判別（券種判別版3）

普通乗車券、指定席／自由席の特急券、グリーン券、指定料金券を読取文字から判別し、券種・座席区分・区間・券面金額候補を表示します。「乗車券＋特急券」「特急券＋グリーン券」などの一体券も区別します。空白や改行で分かれた券名に対応し、別途特急券を求める等の説明文は券名として扱いません。券名が読めなければ未判別、複数回の結果が矛盾すれば不一致と表示します。

特急券・グリーン券の判別は、料金内訳や払戻条件を自動計算する機能とは別です。この読取サイトの計算は引き続き普通片道乗車券の旅行中止のみです。検出した料金券・一体券の合計額を普通乗車券の元券発売額には入力しません。これらは既存MK払戻サイトへのリンクから券種を選んで計算してください。写真の切り出し・横向き撮影・端末内処理を維持しています。
