# 払戻読取

既存MK払戻サイトと独立した、普通乗車券・特急券・グリーン券の旅行中止読取サイト。
既存サイトの計算画面とは独立した /reader/ ページです。

## 使用方法

1. カメラを許可し、回転ロックを解除してスマホを横に持ち、切符1枚を横長の枠いっぱいに撮影します。写真選択も利用できます。背景が多い場合は「切符だけを切り出す」で赤枠を確認・調整します。
2. 「この写真を読み取る」で端末内OCRを実行します。
3. 発着駅・発売額・旅客区分・割引種別を券面と照合し、経由駅を補います。
4. 中止理由と旅行中止駅を入力し、使用開始後・有効期間・入力内容と、運休の場合の購入時期・利用不能条件を確認すると自動計算します。

写真と読取文字はアップロード・永続保存しません。OCR・計算はブラウザ内で実行。
Worker・WASM・日本語モデル・運賃データは同一サイトから取得します。
CSPのconnect-srcをselfに限定し、外部OCRやCDNを使いません。
初回データ取得には通信が必要で、完全オフライン起動は未対応です。
カメラは撮影・閉じる・ページ離脱で停止します。許可拒否時は写真選択が使えます。

## 計算仕様

元券の実発売額 − 元券経路から切り出した既乗区間運賃 − 220円。
割引条件を既乗区間だけで満たす場合は割引運賃、それ以外は無割引運賃を控除します。
営業キロ・混在線換算・運賃表はMK払戻 main 8f463ffを基準に共有。
既存仕様に合わせて未使用営業キロ101km以上を自動計算対象とします。
割引後の10円単位切上げも既存discount_rules.json/Version 5.2に合わせています。
元券発売額はOCR後に券面確認する実額を使い、全区間運賃の再計算額では置き換えません。
根拠：JR北海道旅客営業規則第274条。
https://www.jrhokkaido.co.jp/network/guide/pdf/yakkan_02_07.pdf

## 対象と制限

JR北海道内の登録駅・運賃表による普通片道乗車券、特急券、グリーン券、および確認できる内訳を持つ一体券。
往復/連続、企画券、団体券、市内制度、使用開始前、遅延のみ、送還等の特殊条件は自動計算対象外。運休は利用者による条件確認が必要です。
読み取りは入力補助で、券面の全条件を自動判別するものではありません。
複数金額や割引表示が曖昧な場合は確定せず確認入力に戻します。
経由・有効期間・同行・証明書条件は券面等の確認が必要です。
小児への割引併用は制度条件が未定義のため自動計算を停止します。
対象外券の見落とし、小児判定や金額の誤読、退色・斜め撮影・地紋の強い写真の失敗は残ります。旅客区分が読めない場合は大人に決めず、利用者の確認を必須とします。

## AI読取版4（2026-10-05）

- TesseractからPaddleOCR JS 0.4.2 / PP-OCRv6 tiny detection + small recognitionへ読取エンジンを交換。新たな学習・Claude利用は行っていません。
- 写真から文字領域を検出し、座標に基づいて同じ行を組み立て、離れた発着駅名を解析します。低い認識確度の文字は入力候補から外します。
- 元写真を読み、必要なときだけ青成分を用いた濃さ調整で再読取。金額帯は縦の管理番号を避け、紫色の押印を抑えて追加読取。円記号・認識確度・金額形式がそろう場合だけ補います。異なる候補を勝手に統合しません。
- 撮影・切り出し・回転・特急券/グリーン券判別を維持。料金内訳からの一体券検出、市内制度の対象外チェックを追加。
- OCR Worker、モデル、WASMは同一サイト内に同梱。外部OCRは呼び出しません。Workerの通信も同一オリジンに制限。写真や読取文字の保存・送信はしません。
- 初回データ約46MB。ページ内ではエンジンを再利用し、2枚目以降の起動負荷を減らします。キャンセル時はWorkerを終了します。
- 公開写真25枚を元写真・手動切り出しなしで再読取。登録発着駅のある2枚では駅ペア一致1/2→2/2、普通運賃6枚では発売額一致4/6→4/6でした。金額の全体一致率は改善していません。旧方式で失敗した170円を読める一方、220円など2枚は未判別です。出典・期待値・新旧比較は [benchmarks/results-v4.json](benchmarks/results-v4.json)。写真は配布しません。小標本でありスマホ全般の精度を表す数値ではありません。

### 再ビルド

`npm ci --prefix reader/ocr-build`、`npm run build --prefix reader/ocr-build`。
SDK/ONNX Runtime/OpenCV/ビルド依存を固定。配布モデルとWASMはvendor/paddle-v4内。モデル公式URLとSHA-256はmodels.json、ライセンスはNOTICE.mdとlicenses/を参照。

### 写真比較を再実行

`npm ci --prefix reader/ocr-build` と `npm ci --prefix reader/benchmarks` の後、リポジトリを8765番ポートで配信し、`node reader/benchmarks/run.mjs /写真フォルダの絶対パス` を実行。
sample-00.jpg〜sample-24.jpgは出典一覧に合わせて各自用意してください。結果は写真フォルダのreader-benchmark-v4.jsonに保存。ブラウザと同じ認識関数・画像寸法・追加金額帯・再読取条件を使用します。カメラ撮影や端末性能の測定ではありません。

## 券種の判別（券種判別版3）

普通乗車券、指定席／自由席の特急券、グリーン券、指定料金券を読取文字から判別し、券種・座席区分・区間・券面金額候補を表示します。「乗車券＋特急券」「特急券＋グリーン券」などの一体券も区別します。空白や改行で分かれた券名に対応し、別途特急券を求める等の説明文は券名として扱いません。券名が読めなければ未判別、複数回の結果が矛盾すれば不一致と表示します。

特急券・グリーン券の判別は、料金内訳や払戻条件を自動計算する機能とは別です。AI読取版6では料金券にも中止理由別の使用開始後払戻を追加しています。検出した料金券・一体券の合計額を普通乗車券の元券発売額には入力しません。未使用券や対象外の取扱いは既存MK払戻サイト等で確認してください。写真の切り出し・横向き撮影・端末内処理を維持しています。

## AI読取版5：HEIC写真と料金内訳（2026-10-05）

iPhoneのHEICをネイティブで開けないブラウザでは、同梱したheic-to 1.5.2のCSP対応版を必要時だけ取得し、端末内で画像を展開します。追加データは約3MB。外部変換サービスは使用しません。失敗時は日本語でJPEG・カメラ撮影を案内し、前の写真と入力を残さないようにしました。変換中は操作を制限し、中止後に遅れて完了しても反映しません。

利用者提供のHEIC写真は旧版で画像のデコードに失敗することを再現しました。写真を公開せず、ローカルで形式変換からOCRまで検証します。

特急券・グリーン券等は、区間・合計額に加え「内訳」欄の料金を表示。明示された各券種の料金がすべて読めて、合計と一致する場合だけ内訳を確定します。読取結果が矛盾した場合は保留し、金額を推測しません。対象外の券では普通乗車券用の計算フォームを隠し、MK払戻へのリンクを表示します。この段階では料金券の計算は未対応でしたが、AI読取版6で中止理由別の使用開始後計算を追加しました。

HEICライブラリのライセンス・ソース・再ビルド案内はvendor/heic-v1/NOTICE.md。`npm run build --prefix reader/ocr-build` で固定した依存から配布物をコピーします。

## AI読取版6：中止理由と中止駅による払戻計算

読取後は「お客様都合／列車の運休」と旅行中止駅を入力し、券面・使用開始後・有効期間等を確認すると自動計算します。計算ボタンからも再計算できます。発着駅・経由駅・発売額・一体券内訳は修正できます。券種別の金額・理由・根拠・未使用区間・営業キロ等を表示し、計算に使う条件を変えた場合は再確認するまで以前の結果を消します。

- 普通乗車券・通常：既存の発売額－既乗運賃－220円を維持し、未使用101km未満は自動計算対象外。
- 普通乗車券・運休：未使用区間普通運賃に元券の割引率を適用し、10円単位切上げ。未使用区間だけの割引距離条件は問わず、券面発売額を上限とします（第239条、第282条の2第1号）。元券の割引条件・同行条件は確認します。
- 特急券・グリーン券・通常：使用開始後の区間短縮による払戻は0円。普通乗車券の差引式を料金券へ流用しません（第249条第2項、第252条第8項、使用開始前料金券払戻条件）。
- 特急券・グリーン券・運休：事由発生前購入を確認し、指定列車／グリーン車の全部または使用開始後の一部を利用できなかったかを別々に確認。条件を満たす料金のみ全額、手数料0円（第282条の2第2・3号）。着駅中止・全区間利用済みの料金は0円。未確認は計算を止めます。
- 一体券は各券種の発売額を分け、合計一致を必須にします。普通運賃に料金券分を混ぜません。市内制度、企画・団体・往復等の券は引き続き自動計算対象外です。
- 列車名が「北斗○号」と明確に読めた場合に限り、札幌〜函館の登録経路から発着駅間に含まれる南千歳・東室蘭を経由候補として補います。逆方向・途中区間にも対応。一般の列車名や読めない経路を推測せず、券面確認を必須とします。

運休の分岐は既存事故払戻の条件確認を踏襲し、読取ページの普通運賃割引は公式第282条の2に合わせています。既存サイトのapp.js・index.html・データは変更しません。使用開始前、遅延のみ、他経路乗車・送還・特殊商品等の別取扱いは追加していません。写真は従来どおり端末内で処理し、外部送信しません。

根拠：https://www.jrhokkaido.co.jp/network/guide/pdf/yakkan_02_07.pdf
料金券使用開始前条件：https://www.jrhokkaido.co.jp/network/guide/pdf/rule_19.pdf
北斗の経路参考（2026年3月改正）：https://www.jrhokkaido.co.jp/CM/Info/press/pdf/20251212_KO_kaisei.pdf

## 確認欄の表示（6.2）

文字を読み取れても券種が計算対象外の場合、以前は「02 内容を確認する」全体を非表示にしていました。確認欄を常に表示し、対象外券・個別条件のある券・券種の読取不一致では読取区間、金額候補、判定理由、再読取の案内を表示します。対象外の計算フォームは非表示とし、計算対象を拡張しません。写真の削除・入替時に案内とフォーム表示をリセットします。

## 札幌市内制度（6.3）

払戻読取のみ対応。MK払戻のプログラム・運賃表は変更しません。札幌市内発・着の券面を認識し、中心駅（札幌）と市内の実際の乗車駅・下車予定駅を別々に確認します。読取に失敗した場合は市内発・着のチェックで修正できます。対象駅はJR北海道の公式ゾーン図（rule_10.pdf）によります。他都市は北海道内経路データがないため未対応です。

元券は中心駅から営業キロ200km超の条件を確認。通常中止の既乗区間は、短縮後も中心駅から200km超の場合は第86条により中心駅基準、200km以下の場合は実際の乗車駅基準で第274条の控除運賃を計算します。未使用区間101km以上・220円・元券割引の既乗区間条件を維持。事故の札幌市内着では、第282条の2第1号ロにより中止駅から札幌駅までを払戻運賃の基準とします。結果に券面区間、実乗駅、下車予定駅、中心駅、既乗区間の計算基準を表示します。

発側の市内での中止、着側の市内での事故中止、市内再進入、重複経路は個別取扱いの理由を表示して計算を保留します。通常の市内着で市内まで到達した場合は未使用101km条件を満たさず払戻対象外になります。企画券・トクだ値は商品固有条件が未実装のため引き続き保留。OCRの「値／值」の揺れでもトクだ値を制限します。札幌市内を中心駅へ置き換えるだけで、すべての券を計算対象にする処理は行いません。
